> 模块 key `video`。页面 `src/pages/VideoLabPage/VideoLabPage.tsx`（1006 行）+ 数据层 `src/lib/video-lab.ts`（445 行）。
> 媒体与字幕在 **IndexedDB 独立的 `media` 表**，进度与"上次开着哪一课"在 `safeStorage`。守卫 `scripts/verify-video-lab.mjs`（152 条）· 真界面走查 `scripts/walk-video.mjs`（53 条）· 真媒体探针 `scripts/probe-real-media.mjs`（52 条，两遍 ×26）· 真机行为核验 `scripts/check-video-on-phone.mjs`（10 条）· 素材工具 `scripts/make-video-lab-packs.mjs`。

## 1. 功能

导入 **字幕（必需）+ 视频/音频（可选）**，然后像「每日英语听力」那样逐句学：

| 能力 | 入口 | 落在哪 |
|------|------|--------|
| 逐句跳转 / 单句循环 / A-B 复读 / 倍速 | 卡面按钮（`:800-840`）+ 快捷键 effect（`:618-634`） | 时间轴由 `timeupdate` 驱动 |
| 字幕清单 | 默认只渲染活动句前后 40 条，「展开全部」给整本（窗口常量 `:44`、取窗口 `:604`、按钮 `:972-977`） | — |
| 点词查词 | 词面 span（`:855-863`） | 释义来自词库 `queryWords` |
| 加进生词本 | 查词卡按钮（`:943-949`） | `addCustomWord` → **进 SM-2 复习队列** |
| 收藏句 / 收藏词 | 心形按钮（句 `:868-871`、词 `:952-956`；写点 `toggleFavSentence :476-487`、`toggleFavWord :462-474`） | `useFavorites`，句用 `type:'video'` |
| 朗读本句 | `tts.speak`（`:824-828`） | 全站 TTS 降级链 |
| 跟读比对 | Mic 按钮（`:830-835`，判定 `shadowThis :489-536`） | `SpeechRecognition` + `scoreSpeech` |
| 听写这句 | 键盘按钮（`:872-876`） | 句子拼写的 `video` 桶 |
| 双语字幕 | 「翻译字幕」（按钮 `:836-840`，调度 `:539-599`） | AI 批量翻译 → IDB `z:` 分键 |
| 播放器吸顶悬浮 | 往下滑 → 播放器钉在这一屏顶上并收到 58% 宽（`:779-787`） | 见 §3.6，**必须在自己的滚动容器里才成立** |
| 没有原声时怎么办 | `toggle` / `replayCur`（`:434-448`）没有 `<video>` 就退化成朗读本句；播放器位置写「仅字幕课程」（`:789-793`） | — |

## 2. 为什么是"导入"，不是内置转录（架构决定，别翻烧饼）

本地转录服务（dshzmd，`127.0.0.1:8848`）**不能**作为三形态的共同后端：

- 网页版跑在 `https://nativethink.pages.dev`，去抓 `http://127.0.0.1` 是**混合内容**，浏览器直接拦；
- APK / 桌面根本没有那个进程；
- 服务端也没开 CORS（2026-10-18 讨论过可以加，加完仍然解决不了前两条）。

所以定死的形态是：**用户在转录伴侣里导出 SRT / VTT / JSON，导入 NativeThink**。NativeThink 只在导入这一步之外用自己的能力（查词、收藏、朗读、生词本、拼写、AI 翻译）。界面文案与守卫都按这一条写，不要看到"没接上本机服务"就当缺陷去补网络调用。

## 3. 实现方法

### 3.1 字幕解析与导入分类（`video-lab.ts:58-210`）

| 函数 | 行 | 干什么 |
|------|----|--------|
| `parseTimestamp` | `:63` | `00:01:02,500` / `01:02.500` / `750` → 秒；**认不出返回 NaN**，由 `normalize` 丢条，绝不猜成 0 |
| `stripCueTags` | `:74` | 剥 `<i>` `<c.yellow>` `{\an8}` `v 说话人:` 与 `&nbsp;`/`&amp;` 实体 |
| `parseSrt` / `parseVtt` / `parseDshJson` | `:100` / `:117` / `:129` | 三种格式；VTT 的 `NOTE` 块跳过；JSON 带词级时间戳 |
| `detectSubtitleFormat` / `parseSubtitle` | `:152` / `:160` | **按内容**判格式，判不出按 SRT 兜一次（很多导出文件没有头部） |
| `normalize` | `:85` | 丢无效时间与空文本 → 按 `t0` 排序 → **重新连续编号 `i`** → `t1 ≥ t0` |
| `splitImportFiles` | `:181` | 一次拖进多个文件（视频 + 字幕）的分类**唯一口径**：先看 MIME，再按扩展名兜；`.srt.mp4` 归媒体、`{name:'b.txt',type:'video/mp4'}` 归媒体 |
| `lessonId` | `:192` | 文件名 + 时长 + 字节的哈希，重复导入同一份只有一条 |

### 3.2 存储：三键分片 + 索引封顶（`video-lab.ts:223-300`）

一个 object store（`idb.ts:14` 的 `MEDIA_STORE='media'`），三条键：

```
video-index          → { items: IVideoMeta[] }          （列表唯一权威源）
m:<id>               → { blob }                          媒体本体（可无）
s:<id> / z:<id>      → { sentences } / { zh[] }          字幕与译文分开
```

六条不显然的规定：

1. **`media` 必须独立成表**（`idb.ts:12` 的 `DB_VERSION=2` 加表）。`idbClear()` 只清 `wordbank`，词库重建/换代绝不允许顺手把用户的视频删掉。
2. `save()` 任何一步写失败**返回 false 且不写索引**（`:236-250`）—— 不留半条课程。
3. 索引记录的键名字面量由 `INDEX_KEY`（`:58`）单点提供，守卫**用码点拼出期望值**钉住它：这个值一度是三个星号，功能完全正常（它只是个唯一键名），所以真跑断言与走查一路全绿 —— 直到探针把 `getAllKeys()` 原样打出来才看见。改键名会让已存在的索引记录变孤儿，本模块刚上线、无真实用户数据才敢直接改。
4. 索引 50 条封顶，淘汰旧条目时**连 `m:`/`s:`/`z:` 一起删**（`:243-249`）。只删索引会留下几百 MB 孤儿 blob。
5. 译文分键回写（`saveZh` `:274-281`）：AI 翻译不重存 blob，只写 `z:`；写失败如实返回 false，界面显示"这次只显示、下次要重翻"。
6. `load()`（`:253-272`）把 blob 换成 object URL 前判 `instanceof Blob` 并 try/catch —— 记录被写坏时退化成"无原声"，不许把页面掀翻。

`withStore` 的 resolve 挂在 `tx.oncomplete`（`idb.ts:48-62`，`tx.oncomplete` 在 `:58`）而不是 `request.onsuccess`：配额满的失败是**事务级**的，只看 request 会把没落盘的写当成成功。

### 3.3 播放、计时与断点

- 活动句：`activeIndexOf`（页面 `:80`）线性扫，`timeupdate` 驱动（`:352-373`）。单句循环与 A-B 都在这一个回调里，避免两套时间判定。
- **课时一律取字幕末秒，不取容器/JSON 的时长**：`durationOf(parsed)`（`:89`）同时喂给 `lessonId`（`:298`）与 `meta.duration`（`:300`）。为什么：转录伴侣导出的 JSON 里 `duration` 记的是**整条原片**（01 那课是 6024 秒 ≈ 100 分钟，`video-lab.ts:144` 会原样带出来），而素材包里的媒体只是其中 344 秒那一段；`parseSubtitle` 的返回值里那个 `duration` 页面**不许直接用**，否则界面顶上就是「0:00 / 100:24」，播放器一路空转、句子还停在最后一句 —— 用户读到的是"时间线自己乱跳"（守卫与探针各钉一条）。
- **计时按课去重**：`reachedRef` 是 `Map<课 id, Set<句序号>>`（`:154`、`:363-366`），`addStudyMinutes(0.2,'video')` 只在"这一课第一次推进到这一句"时给。两个方向都不能错：只按句序号去重（全局一份 Set）的话，换一课的同序号句子永远不再计时长；不去重的话往回拖一遍就刷一遍。`verify-study-credit` 钉"到新句才计 + 本地动作不套闸门"，`probe-real-media` 第 ⑭ 测用真原声跑出 `0.2 → 0.3 → 0.3`（认新句加、同句来回拖不加）。
- 进度：`mergeProgress`（`video-lab.ts:304`）封顶 80 课，经 `persistJson` 写 `__nativethink_video_progress`（键名 `:40`，落盘 effect `:378-387`）→ 自动进云同步与备份。删课要连这条记录一起删（`:273`）。
- 断点：`__nativethink_video_last_open`（键名 `:42`、写入 `:254`、恢复 effect `:259-266`）。切 tab 会重挂载组件（`Layout.tsx` 的 `key={location.pathname}`），回来必须接着上次那一课；主动点返回箭头要清掉这个键（`removeLesson` 与返回列表处），否则下次进来又被拽回课程、看不到导入入口 —— **`nav` 是整页重载，走查里要从课程视图点回列表才谈得上"回到空态"**。

### 3.4 点词 / 收藏 / 跟读 / 听写 / 翻译

- **词面必须两种形态都能点**：JSON 字幕带词级时间戳，普通 SRT 没有 —— 没有时按空白把整句切成词 span（`:855-863`）。早期版本把整句当一个 span，结果"点词查词"在最常见的那种字幕上退化成"点整句"（2026-10-18 走查抓到，守卫第 ⑤ 节钉住）。逐词高亮只在真有词级时间戳时点亮，否则整条一起下划线没有意义。
- 查词：先 `queryWords({search, limit:1})`，**查不到先 `preloadCoreOnly` 预热再查一次**（`:452-460`），否则核心层没预热时会假报"词库里没有这个词"。
- 收藏句：`type:'video'`，`example` 存 `起始–结束` 时间区间（`:476-487`）。判重必须 `isFavorited(content,'video')` **看两 type**（与全站口径一致，见 dashboard-progress-favorites.md）。收藏页三处已认得这一型：标签 `FavoritesPage.tsx:38`、配色 `:51`、筛选 `:56`。
- 跟读评分：`scoreSpeech`（`video-lab.ts:343`）用 **LCS 按词序**算命中比例并列出漏读词。不许用集合交集 —— `"the book is on the table"` 里 `the` 出现两次，只读对一次不该算两次。**通道判定不能只看对象存在**：模拟器 APK 实测 `window.webkitSpeechRecognition` **存在**（`sr:true`），但 `start()` 之后 onresult/onerror/onend 一个都不回 —— 所以除了 `!API` 那条"这台设备没有语音识别通道"的实话文案，还要 **try/catch 兜 `start()` 当场抛**、再加 **9 秒看门狗**（`rec.start()` 后无回应就收摊并说明"识别服务没有回应"，同时撤按钮的"正在听…"态）。三者缺一个就是 AGENTS 那条"点了没反应／转圈不结束"（2026-10-18 装机走查抓到：改之前正是卡在"正在听…"）。卸载时 `recRef.current?.abort()`（`:178`）+ 撤看门狗（`:513` 那个 9 秒）。绝不允许显示一个假分数。
- 听写这句：`videoToSpellingItem`（`use-spelling-sentences.ts:74-76`）是单一口径，与纠偏桶共用 `sentenceItem`（`:58-71`，判难 ≤7 / ≤13 / 更多）。拼写页里 `video` 是**句子库的桶**、不是词库：`handleLevelChange` 与纠偏桶共用同一条早退分支（`SpellingPage.tsx:883`），否则会 `preloadLevels('video')` 并弹「该词库没有例句」。桶名在词库下拉 `:1299-1306`，标签映射 `:1262`。按钮"这句已经在听写本里"用 `normSentenceKey` 判（页面 `:162`、渲染 `:872-876`），是界面状态不是 toast。
- **素材必须有画面，而且媒体由出包工具统一压一遍**（用户硬要求："导入的素材必须要有画面"、"画质不需要太好"）：`make-video-lab-packs.mjs` 先 `ffprobe` 源媒体，**没有画面轨直接拒绝出包**（加 `--allow-audio` 才放行），有画面的那份再走 ffmpeg —— **scale 到 ≤480p + H.264(`libx264`) + `yuv420p` + `+faststart` + AAC 96k，并 `-t 字幕末秒+2` 裁到字幕覆盖的区间**。B 站"听力号"类上传常见两种坑：① 只给音频流（`bestaudio`）→ 播放器整块黑；② 480p 给的是 **AV1** → WebView 不保证解得动，所以选流时就限定 `vcodec^=avc1`，转码这一步再兜一层。为什么必须在工具里做：手机要把整份媒体塞进 IndexedDB，那条 1080p / 4.9 分钟的新闻原片 35MB，压完是个位数 MB；那条 100 分钟的合集也是裁到 344 秒才对得上 69 句字幕。**已经有画面轨的成品媒体会被沿用**（手工裁好的那份不会被音频源覆盖，拒绝出包时也只删本次新写的文件，不动已有课包）。App 侧也补了实话：`el.videoWidth === 0 && el.videoHeight === 0` 时在播放器下写"只有音频轨、没有画面，黑屏属正常"。
- **真机看画面要用 `adb exec-out screencap -p`，不要用 `device-eval shot`**：后者走 CDP `Page.captureScreenshot`，**抓不到视频硬表面**，播得好好的也会截成一块黑（本轮差点据此误报"没有画面"）。量化对照：源文件抽帧平均亮度 51.9，设备截屏播放器区域 53.3 / 256 级灰阶，而 CDP 截图那块是全黑。
- **假时长要说破**：流媒体站给的 m4a 常见"容器头写 100 分钟、实际只有 5 分钟"（截断下载；实测 B 站那条头 6024s / 真语音 343s）。`onLoadedMetadata={checkDuration}`（`:405`）用**双向比值**判（`got/expect > 1.6 || < 0.6`，不只判 NaN），命中就在播放器下方一行写清"播放器报多少、字幕只到多少，跳转/复读按字幕时间走"（渲染 `:796-802`；换课时 `setNote('')` 清掉，见 `:241`）。素材侧另用 `ffmpeg -t <字幕末尾秒+1> -c:a aac` 重编，`ffprobe` 复核 duration 才算修好。
- 双语字幕（用户 2026-10-18 反馈「翻译字幕功能很慢」后重做）：**调度在 `runBatchTranslation`（`video-lab.ts:411` 起），页面只喂通道（`VideoLabPage.tsx:539-599`）**。参数：一次最多 `TRANSLATE_LIMIT=120` 句（整课一次覆盖，不再要用户点三次）、每批 `TRANSLATE_BATCH=8` 句、串行 `concurrency: 1`、每批看门狗 `TRANSLATE_TIMEOUT_MS=25000`（`:47/:60/:62`）。
  - **实测数据（本机 → Pages 中继 → 智谱免费档，同一段 69 句）**：串行每批 3.2–4.5 秒；**起 3 路并发后每批拖到 8–30 秒，并且遇到过一整路永不回包**。`functions/api/ai/chat.js:46` 写着「免费档并发仅 1」，所以并发不是可用的加速手段 —— 抢并发只会把总时长从 10 秒拖成 60 秒。指定翻译任务档（`task:'translate'` → glm-4.7-flash）实测单批 23s/62s，更慢，也就不用（整书翻译那条后台链路才值那个准确度）。
  - 因此"快"只能来自**边翻边上屏**：每批完成立刻回调 → `setLesson` 增量上屏 + `saveZh` 落盘（`:573-582`，落盘走串行队列写最新快照，避免并发覆盖）。旧写法是整轮 `for` 串行、最后一次性 `setLesson`，实测 30 句要 10 秒且这 10 秒里界面一动不动。
  - **走查实测的凭据**（`walk-video.mjs` 第 ⑧ 节）：点下去按钮立刻变成「开始翻译 45 句…」并禁用 → 中途按钮还写着"翻译中"时界面已经出现一部分中文行（`带中文的字幕行 0 → 40`）→ 结束时回报「已翻译 45/45 句」，**一次点击覆盖整课**（旧写法 69 句要点三次、每次 10 秒全程无反馈）。
  - **每批必须有超时**：AI 请求挂住不会抛错（`use-ai.ts` 把失败收成 `''`，挂住则连 reject 都没有），没有这道看门狗按钮就永久停在"翻译中"——与跟读那条「接口存在≠通道可用」同族。
  - 坏批处理：单批拿不到内容**退回队尾重试一次**（`video-lab.ts:407-412`），**连着两批坏才整轮收摊**（先判收摊、再谈重试，顺序反了就变成无限重排 —— 守卫用变异钉住）。已翻好的落 `z:` 不动，剩下的算进 `missed`，文案写"再点一次重试剩下的"。三档降级各有实话：未配 Key / 一句都没回来（含超时）/ 部分没回来。
  - 在途锁 `translateRunning` 是**模块级**（`:58`）而不是 ref：组件每次导航都重挂载会重置 ref，而模块级的一份才拦得住"两课同时翻"。锁在 `finally` 里连同按钮态一起释放，早退（换课）也解。
  - 换课/卸载：`shownIdRef` + `activeRef` 让旧轮次停止取新活，但已经在途的那批回来仍写回**它自己那一课**的 `z:`（`:575`；`stopped()` 在 `:570`/`:577`，`shownIdRef` 在 `:156-157`）；`openLesson` 清掉上一课的"翻译中/结果文案"（`:241-242`）。
  - 编号 JSON 的解析**复用整书翻译的 `parseBatchTranslation`**（`data/book-translation.ts:196`），不另写一份正则；`ask` 的第二实参必须是**该批自己的句数**（页面用它算 `maxTokens`，传成整课句数会把上限放大到 3800）。

### 3.5 播放器吸顶悬浮（`paneH` / `boxRef` / `canPin`）

用户 2026-10-19 的口径："往下滑视频一直悬浮在上方，往上滑回顶又能回到之前的样子，能同时查找字幕和视频"。做三件事：**这一屏自己成滚动容器**、**吸住时收画面**、**给释义卡留避让**。

- **为什么必须自建滚动容器 —— 这条是量出来的，别照着 CSS 直觉改**。临时页 `scripts/probe-sticky.html` 四个变体逐个实测（读 sticky 元素的 `getBoundingClientRect().top`）：
  | 变体 | 结果 |
  |---|---|
  | 只有文档滚（外壳照抄：`SidebarInset` 带 `overflow-x-hidden`、`main` 不带 `overflow-y-auto`） | **不吸**，`winTop` 跟着 scrollTop 走到 −228 / −628 |
  | 再把 `main` 换成 `overflow-y-auto` | 仍不吸 |
  | 去掉 `SidebarInset` 的 `overflow-x-hidden`（其余照旧） | **吸住**，`winTop` 恒为 0 |
  原因是 `overflow-x: hidden` 配 `overflow-y: visible` 时，规范会把**计算出的 overflow-y 变成 auto**（`Layout.tsx:115` 那句 `overflow-x-hidden` 因此自己就成了一个滚动容器），而 `main`（`:117`）又明写着 `overflow-y-auto` —— 可这两层的高度都随内容长（外层只有 `min-h-screen`，没有任何一层把高度钉在视口上），**真正在滚的一直是文档**（实测 `main.scrollHeight − main.clientHeight = 0`）。sticky 的约束根是"最近的滚动容器"，所以它相对一个从不滚的盒子算偏移，永远不吸。
  → 这一课把滚动收进自己这层框：`paneH` 钉高度（`window.innerHeight − 本层在文档里的绝对 top − main 的 padding-bottom`，`:192-207`），内容进 `boxRef` 那个 `overflow-y-auto` 的框（`:766-768`）。**没有动外壳**：把 `main` 改成真滚动容器会牵动全站（路由复位的 `window.scrollTo`、语块库那条"单一滚动权威"、各页 `pb-20` 的让位），风险远大于一个页面的收益。
- **量不到就不限制**：`paneH` 只在能找到 `main` 时才写，否则 `0` → 界面回到"整页随文档滚"，不吸顶但绝不裁内容。`canPin = paneH >= 480`（`:145`）再挡一层：窗口太矮时吸住等于用播放器盖住整个滚动框，那种尺寸下**不吸**才是对的（探针在 400×860 视口下吸得住，在更矮的窗口里就该走这条路）。
- **吸住的判定**：播放器上方 1px 哨兵（`:781`）+ `new IntersectionObserver(…, { root: box, threshold: 0 })`（`:214`）。**拿 `closest('main')` 当根判不到**（那条 main 从不滚，实测永远 `isIntersecting`）；守卫点名这条，变异"不给 root"必红。
- **收画面要收宽度而不是收 `max-height`**：手机上的视频是**被宽度限住高度**的（393 CSS 宽 16:9 → 约 209px 高，`46vh`/`30vh` 都碰不到它），只改 `max-h` 等于没缩。所以吸住时 `w-[58%] mx-auto`（`:787`），400×860 实测 265px → 154px，字幕从"看不见"变成"看得见一片"。
- **`[overflow-anchor:none]`（`:767`）不能撤**：吸住那一瞬画面收档 → 下方内容整体上移 → Chrome 默认"锚住可见内容"会顺手改 `scrollTop` → 哨兵被挪回视口 → 解除吸住 → 画面长回去 → 再吸，短句课上来回抖。B 遍负对照就是这么抓到的（同一测两次读数 `190px→7` / `181px→0`）。收的是播放器自己的高度，哨兵在它**上面**，位置本不该变 —— 所以关掉这个自动补偿才是对的。
- **避让值取实测，不许写死 `calc`**：吸住后播放器压在滚动框顶上，而释义卡的 `scrollIntoView({block:'nearest'})` 只认可视区、不知道有遮挡。用原生的 `scroll-padding-top` 让开，值 = 量出来的播放器底边（`:224-232`）。写死 `calc(30vh + 6rem)` 在矮窗口会猜得比滚动框还大，`scrollIntoView` 只能"尽力而为"，实测卡片仍旧压在播放器底下（卡顶 346 vs 播放器底 335）。
- **只在有媒体的课上吸**：仅字幕课没有画面可悬浮，`lesson.url && canPin && 'sticky top-0'`（`:782`）。

## 5. 注意事项

1. **object URL 必须 revoke**：卸载 effect（`:177`）、换课（`:239`）、删课（`:278`）、主动返回列表（`:770`）——四处都撤，少一处就是几十 MB 的 blob 泄漏。几十 MB 的 blob 泄漏比缓存贵。
2. **字幕列表必须开窗**，但「展开全部」不许削弱（守卫 `verify-list-scaling` 同款口径；`verify-video-lab` 第 ④ 节钉窗口常量）。
3. **无媒体是合法形态**：只导字幕时播放器位置显示"仅字幕课程 · 用朗读本句"（`:789-793`），不是坏掉的 `<video>`。
4. 卡面大量动作是**图标 + title**（收藏这句、送进句子拼写）。自动化按 title 精确匹配，按 innerText 找不到（walk-video 的 `clickTitle`，与真机走查同一条教训）。
5. 快捷键监听用**捕获阶段**（`:632`），否则 Radix 冒泡阶段同步关弹窗会把 Esc 连带退出流程。
6. 本页**零 toast**：所有反馈走界面文案（查词卡、跟读块、译文进度行）。新增提示必须先改守卫的零提示断言。
7. `accept="video/*,audio/*"` 这个属性里的"斜杠星"会**骗过任何用正则剥注释的静态检查** —— 从那里一路吃到后面真正的注释结尾，一次吞掉 9KB 源码，接线断言全变成"这段代码不存在"的假红。`verify-video-lab.mjs:26-32` 因此把剥注释交给 TS 转译器（`removeComments`），并自带一条脚手架自证。
8. **改守卫/走查前先用 grep 核对磁盘上到底是什么实现**。本轮（2026-10-19）栽了两次：编辑器把**上一会话的文件文本**当现状返回（页面里那个 `claimCredit` + `creditedRef` 版本、走查里那节"⑫–⑰"都不在磁盘上），于是照着不存在的代码写断言、还报告"改动成功"。真实现是 `reachedRef: Map<课 id, Set<句>>`（`:154`）。判据只有一个：`grep -c`/`git diff` 看磁盘，别看工具回显。
9. **素材的时长对齐要靠工具，不要靠手工记忆**：出包时媒体按 `-t 字幕末秒+2` 裁（`make-video-lab-packs.mjs:208`），事后用 `check-video-lab-packs.mjs` 逐课实测复核 —— 六课的"媒体末秒 − 字幕末秒"全是 2 秒。**别再凭读到的数字改代码**：本轮一度以为"媒体 3:38 / 字幕 5:28"是素材坏了，据此写了裁剪+平移 cue 的改动，实测下来那份素材根本没问题，改动反而会把已裁好的课包弄成不同步（媒体不动、字幕平移）。
